Two systems, one hundred items, and no agreement on what anything is called.

During a NetSuite migration this summer, I reconciled item records by hand across four client systems. This is that job rebuilt as a pipeline, on synthetic data. Plain code matches the easy rows. An LLM is asked only about the ones code can't settle, and has to give a reason. Anything it isn't sure of, and every real conflict, goes to a person.

      What this doesn't prove

      I designed the mess. The abbreviations here (Blk, Std, Frm Stl, Pwdr) are the kind a language model reads easily. Real legacy data has internal shorthand, typos, and fields that mean different things in different systems.

      The samples are small. About 35 rows per dataset reached the model. A clean result on 35 decisions is encouraging, not conclusive.

      Each dataset was run once. Model output can vary between runs, so a production version would need repeated runs to measure consistency.

      The held-out set came from the same generator. A new seed means new items and new placements, but the same kinds of problems. It shows the thresholds weren't tuned to one dataset, not that the tool handles every kind of mess.

      To run it yourself, clone the repo and follow the README. The code-only pipeline runs without an API key: python generate_data.py 123, then python reconcile.py --no-llm.
